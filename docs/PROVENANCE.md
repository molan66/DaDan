# 来源与改写范围说明（PROVENANCE）

本文件逐项说明本项目与上游项目 [sona](https://github.com/WJZ-P/sona)（AGPL-3.0）
之间的关系：哪些功能是参考上游改写的、改到了什么程度、哪些部分是本项目独有的。

写作目的有两个：一是履行 AGPL-3.0 第 5(a) 条"显著标注已修改"的义务，
二是让使用者能自己判断本项目的原创程度，不必依赖作者的自述。

## 一句话结论

**本项目不是 sona 的移植，也不是独立实现。** 它是用完全不同的技术栈
（Python + PyQt5 直连客户端 LCU 接口）重写的一个客户端辅助工具，其中
**4 个功能的实现思路、常量表和部分注释文本参考甚至改写了 sona 的对应文件**。
改写的原始依据是上游公开的 TypeScript 源码在 GitHub 上可读，本项目**没有**
复制其 JavaScript 代码体，也没有复制其 DOM / CEF / Pengu Loader 相关代码
（本项目不注入客户端进程，不存在这类代码）。

## 逐项对应关系

下表列出的功能，本项目的实现参考了上游对应文件的设计与逻辑。表中"改写程度"
一栏依据的是**代码注释文本重合度**与**常量表比对**，判定方法见下一节。

| # | 本项目位置 | 上游对应文件 | 功能 | 改写程度 |
|---|---|---|---|---|
| 1 | `core/script_core.py` 自动接受一节 | `src/lib/features/auto-accept.ts` | 每次 ReadyCheck 只接受一次；用户主动拒绝后暂停接受直到回到大厅；接受延迟上限保护 | **较高**。逻辑结构与常量（15 秒上限）一致；注释文本重合 |
| 2 | `core/script_core.py` 自动点赞一节 | `src/lib/features/auto-honor.ts` | 对局结束后给队友点赞：票数分配、随机打散、随机荣誉类别 | **较高**。`HONOR_CATEGORIES = ['HEART', 'COOL', 'SHOTCALLER']` 与上游常量表**逐字节相同**；分支顺序一一对应 |
| 3 | `core/script_core.py` 对局结束返回一节 | `src/lib/features/auto-return-to-lobby.ts` | 对局结束后 playAgain + 重试匹配 | **中等**。重试次数与间隔（15 次 / 1 秒）为上游同量级参数 |
| 4 | `core/script_core.py` / `lcu/api.py` 大乱斗换将 | `src/lib/features/bench-no-cooldown.ts` | 直接调用 API 换将，不做冷却限制 | **较低**。仅"不设冷却"这一行为约定一致，无文本重合 |
| 5 | `ui/main_window.py` 与 `core/script_core.py` 的"拒绝后再接受"控制 | `src/lib/features/ready-check-control.ts` | 允许先拒绝、之后再接受 | **低**。仅设计意图相同 |

### 判定方法与实测数据

比对脚本把两边的**注释与文档字符串**按"连续 ≥6 个中日韩字符"切段后做重合检测
（纯代码行不参与，因为两边语言不同、语法无法直接比对）：

| 上游文件 | 本地注释段命中 / 总段数 | 命中率 |
|---|---|---|
| `auto-honor.ts` | 6 / 11 | **54.5%** |
| `auto-accept.ts` | 15 / 35 | **42.9%** |
| `auto-return-to-lobby.ts` | 2 / 11 | 18.2% |
| `bench-no-cooldown.ts` | 0 / 8 | 0% |
| `ready-check-control.ts` | 1 / 47 | 2.1%（噪声级） |

同时核对了上游特有的 20 个 camelCase 标识符（如 `autoHonor`、`benchSwap` 等），
**本项目代码中一个都没有出现**；上游 33 个功能文件里，本项目只实现了上表 5 项。

结论：重合集中在"自动接受"与"自动点赞"两处，表现为**中文注释文本、常量表、
少数几行局部逻辑**的相似，不是整文件翻译。这两处已在 `core/script_core.py`
的模块文档字符串里逐条标注了上游出处。

## 本项目独有的部分

以下部分在 sona 中**没有**对应物，是本项目自有的：

- **客户端发现与直连**：扫描磁盘定位 `lockfile`，读取端口与 token，直连 LCU 的
  REST 与 WebSocket（上游通过 Pengu Loader 提供的注入环境访问，没有这一步）。
- **屏幕坐标点击兜底**：当接口调用不可用时，按虚拟桌面坐标注入鼠标点击
  （`lcu/clicker.py`），含多显示器负坐标与管理员权限提权识别。
- **界面层全部**：无边框毛玻璃窗口、侧边栏六页、账号卡、对局详情弹窗、
  英雄选择器、悬浮小窗（`ui/` 目录）。
- **账号卡与战绩页**：召唤师信息、段位、钱包与熟练度展示；近期对局列表与
  本局 10 人详情。
- **工程化设施**：日志轮转与脱敏、图标缓存与异步下载、连接探活看门狗、
  并发去重锁与单飞模式、可移植的 PyInstaller 打包配置。

## 图标与文字素材

- 英雄中文名、别名与拼音索引：基于官方公开数据整理（`data/champion_aliases.py`、
  `data/champion_pinyin.py`）。
- 英雄 / 物品 / 符文 / 召唤师技能图标：程序**运行时**按需从 Data Dragon 与
  国服官方 CDN 下载并缓存，**不随本仓库分发**，其著作权归 Riot Games 所有。
- 应用图标（`data/app_icon.png` / `.ico`）为本项目自有。
